# Contrats API et intégrations
Statut : esquisse P ; noms et formes non figés. Produire un contrat OpenAPI validé avant le développement des clients.

## Identité et habilitations (US-06, ADR-10)
| Opération | Accès | Entrées → sortie |
| --- | --- | --- |
| POST /auth/login | Public | e-mail, mot de passe → jeton d'accès (15 min) et jeton de renouvellement ; 401 identique que le compte existe ou non ; 423 si verrouillé |
| POST /auth/refresh | Jeton de renouvellement | jeton → nouveau couple (rotation, l'ancien devient invalide) ; 401 si révoqué ou expiré |
| POST /auth/logout | Authentifié | → révoque le jeton de renouvellement de l'appareil |
| POST /auth/activate | Public, lien à usage unique | jeton d'activation, mot de passe → compte actif, réponse : e-mail du compte (connexion immédiate) ; 410 si expiré ou déjà utilisé |
| GET /me | Authentifié | → identité, organisations (adhésions acceptées), rôles et sites autorisés, invitations en attente |
| POST /me/invitations/{memberId}/accept | Titulaire de l'invitation | → adhésion acceptée, droits effectifs ; 404 sinon |
| POST /me/invitations/{memberId}/decline | Titulaire de l'invitation | → invitation refusée (révoquée, historique conservé) ; 404 sinon |
| GET /organizations/{orgId}/sites | Membre de l'organisation | → sites autorisés pour l'appelant uniquement |
| POST /organizations/{orgId}/sites | Administrateur d'organisation | nom → site créé |
| GET /organizations/{orgId}/members | Administrateur d'organisation | → membres non révoqués : nom, e-mail, rôles par site, invitation en attente, version |
| POST /organizations/{orgId}/members | Administrateur d'organisation | nom, e-mail, rôles, sites → invitation créée ; lien d'activation (montré une seule fois) seulement si le compte est créé par cet appel ; 409 si compte en attente créé ailleurs |
| POST /organizations/{orgId}/members/{memberId}/activation | Administrateur d'organisation | → nouveau lien, si cette organisation a créé le compte et qu'il n'est pas activé ; 409 sinon |
| PUT /organizations/{orgId}/members/{memberId} | Administrateur d'organisation | rôles, sites, version attendue, motif (obligatoire) → habilitations révisées et tracées (RG-31) ; 409 si version dépassée ; sans changement : rien n'est écrit |
| DELETE /organizations/{orgId}/members/{memberId} | Administrateur d'organisation | corps : motif (obligatoire) → accès à l'organisation coupé dès la requête suivante, jeton d'accès en cours compris ; la session du compte reste ouverte pour ses autres organisations (décision du porteur, 28/10) ; historique conservé |
| GET /organizations/{orgId}/members/journal?limite=&avant= | Administrateur d'organisation | → journal des habilitations (RG-31) : nature, auteur, date, motif, rôles avant/après, du plus récent au plus ancien ; pages de 200 au plus, `avant` = identifiant de la dernière entrée reçue |

Rôles : administrateur d'organisation (A), responsable (R), délégué (D), technicien (T), pasteur (P), coordination (C) ; cumulables ; chacun accordé sur des sites précis (A : toute l'organisation). Toute ressource d'une autre organisation répond 404, jamais 403, pour empêcher l'énumération.

## Dépôt public (US-08, S08-01)
| Opération | Accès | Contenu et réponses |
| --- | --- | --- |
| GET /public/sites/{code} | Public | → nom du site et de l'organisation (en-tête du formulaire) ; 404 si code mal formé ou inconnu |
| POST /public/sites/{code}/reports | Public | `commandeId` (UUID choisi par le formulaire), `nature` (Incident ou Demande), `description` (≤ 2000), `emplacement` (≤ 200), `danger`, `activiteBloquee`, `nom` (≤ 200), `contact` (≤ 200, non vérifié) → 200 `{site, danger, numeroUrgence}` : aucun identifiant ni jeton ; `numeroUrgence` seulement si danger et numéro du site renseigné. Même `commandeId` rejoué ou envoyé en parallèle avec le même contenu : même accusé, un seul signalement ; contenu différent : 409 `commande_reutilisee`. 422 `donnee_invalide` + `champ` (corps illisible : `champ` = `corps` ; textes : une ligne visible sans caractère de contrôle ni inversion bidirectionnelle, description multiligne) ; 404 code inconnu. Danger : alerte enregistrée avec le signalement. |

Photos (S08-02) : même opération en `multipart/form-data` — partie `demande` (le JSON ci-dessus) et jusqu'à 3 fichiers `photos` de 10 Mo (JPEG, PNG ou HEIC, reconnus par leurs octets d'en-tête) ; sinon 422 `champ` = `photos`, sans signalement créé. Chaque photo est réorientée, débarrassée de ses métadonnées (position GPS comprise), réduite à 2560 px et réencodée en JPEG, puis stockée en privé sous `organisations/{organisation}/signalements/{signalement}/photo-{rang}.jpg` (clé propre au signalement enregistré ; un rejeu ne réécrit rien). Corps trop volumineux : 422 `photos` ; envoi tronqué : 422 `corps`.

Anti-abus (S08-03) : champ `verification` = jeton Turnstile produit par le navigateur, vérifié par l'API auprès de Cloudflare (clé secrète `Turnstile:CleSecrete` ; absente : 503 `depot_indisponible`, le reste de l'application fonctionne ; `Turnstile:Desactive` refusé hors développement) ; refus → 422 `champ` = `verification`. Un rejeu (même commande, même contenu) n'est pas revérifié : le jeton ne sert qu'une fois. Au plus `DepotPublic:LimiteParSite` signalements acceptés (20 par défaut) par site et par fenêtre de 10 minutes, comptés après l'anti-robot (requêtes invalides et rejeux non comptés) : au-delà, 429 `trop_de_depots` ; la limite par adresse du visiteur est appliquée par l'application web (S08-04).

Inventaire — structure (US-07, S07-01) : `/organizations/{orgId}/sites/{siteId}/inventory/…`
| Opération | Accès | Contenu et réponses |
| --- | --- | --- |
| GET structure | Comptes internes du site (`ConsulterSite`) | → `[{id, nom, niveaux: [{id, nom, ordre}], zones: [{id, nom, niveauId, partiesCommunes}]}]` (bâtiments par nom, niveaux par ordre, « Parties communes » en dernier) |
| POST buildings | T, R/D du site (`ModifierInventaire`) | `nom` → `{id}` ; crée aussi la zone « Parties communes » du bâtiment |
| POST buildings/{batimentId}/levels | Idem | `nom`, `ordre` (−10 à 100, sous-sols négatifs) → `{id}` |
| POST zones | Idem | `nom`, `batimentId`, `niveauId` facultatif (du même bâtiment) → `{id}` |
| PUT buildings/{id}, levels/{id}, zones/{id} | Idem | `nom` → 204 ; « Parties communes » ne se renomme pas (422) ; sans changement, rien n'est écrit |

Erreurs : 422 `donnee_invalide` + `champ` (champ absent compris) ; 409 `nom_existant` (casse ignorée : même nom dans le site pour un bâtiment, dans le bâtiment pour un niveau, sur le même niveau pour une zone — « Sanitaires » peut exister à chaque étage) ; 409 `modifie_entre_temps` (renommage concurrent) ; 404 hors périmètre ou élément absent ; 403 sans rôle de terrain (administrateur seul, pasteur, coordination). Chaque création et modification est tracée dans `patrimoine.journal_inventaire` (ajout seul : auteur, date, valeurs avant et après).


Inventaire — composants (US-07, S07-02) : `/organizations/{orgId}/sites/{siteId}/inventory/components…`
| Opération | Accès | Contenu et réponses |
| --- | --- | --- |
| GET components | `ConsulterSite` | filtres facultatifs `zoneId`, `batimentId`, `corpsEtat`, `verification` (true/false), `recherche` (≤ 200 ; nom, marque, modèle, n° de série, emplacement ; casse ignorée, % et _ littéraux), `retires` (false par défaut) ; un filtre vide est ignoré → `{composants: [composant], tronquee}` par nom, 1000 au plus (`tronquee` si davantage) |
| GET components/counts | `ConsulterSite` | → `[{zoneId, actifs}]` : composants actifs par zone (zones vides absentes), sans limite |
| GET components/{id} | `ConsulterSite` | → `{composant, historique: [{le, nature, auteurCompteId, auteur, apres, avant}]}` (`auteur` : nom affiché du membre de l'organisation, null si inconnu) (plus récent d'abord ; retirés compris) |
| POST components | `ModifierInventaire` | fiche ci-dessous → `{id}` ; `soumisAVerification` absent : proposition du corps d'état |
| PUT components/{id} | `ModifierInventaire` | fiche complète + `version` lue + `soumisAVerification` exigé → 204 ; sans changement, rien n'est écrit |
| POST components/{id}/withdraw | `ModifierInventaire` | `motif` (≤ 500), `version` → 204 ; définitif, le composant reste consultable |

Fiche : `nom` (≤ 120), `corpsEtat` (nom exact : StructureGrosOeuvre, CouvertureEtancheite, MenuiseriesExterieures, MenuiseriesInterieures, RevetementsFinitions, CourantsForts, EclairageSecurite, SecuriteIncendie, CourantsFaibles, ChauffageVentilation, Plomberie, Gaz, Ascenseurs, Paratonnerre, Campanaire, Accessibilite, Mobilier, EquipementsCulte, ExterieursVoirie, Autre), `zoneId` (zone du site), facultatifs `emplacement` (≤ 200), `marque`, `modele`, `numeroSerie` (≤ 120), `anneeMiseEnService` (1000 à l'année en cours), `moisMiseEnService` (1–12, avec l'année, jamais futur), `remarques` (≤ 2000, multiligne), `soumisAVerification`, `lot` absent pour un composant individuel, sinon `{unite: Unite|MetreCarre|MetreLineaire|MetreCube|Ensemble, quantite: 1–100000, repartition?: {bon, satisfaisant, degrade, mauvais, critique}}` (état absent = 0, somme = quantité, RG-10). Composant lu : mêmes champs + `id`, `retireLe`, `motifRetrait`, `version`.

Erreurs (403/404 d'accès toujours avant les erreurs de saisie) : 422 `donnee_invalide` + `champ` (`lot.repartition`, `lot.quantite`, `lot.unite`, `zoneId` absente ou d'un autre site, `version` absente…) ; 409 `modifie_entre_temps` (version dépassée : relire puis refaire), 409 `composant_retire` ; 404 composant absent ou hors périmètre ; 403 sans rôle de terrain. Journal : création (valeurs saisies), modification (champs changés seulement, avant et après), retrait (motif).


Grilles d'évaluation (US-11, S11-01) : `/organizations/{orgId}/sites/{siteId}/inventory/grids…` — une grille par corps d'état et par site (droits du site, PERMISSIONS).
| Opération | Accès | Contenu et réponses |
| --- | --- | --- |
| GET grids | `ConsulterSite` | → `[grille]` pour les 20 corps d'état, version courante |
| GET grids/{corpsEtat} | `ConsulterSite` | → `grille` |
| GET grids/{corpsEtat}/default | `ConsulterSite` | → `{criteres, mesures}` : contenu de la grille par défaut, pour « revenir à la grille par défaut » (enregistré comme nouvelle version) |
| PUT grids/{corpsEtat} | `ModifierGrilles` (responsable, délégué) | `criteres` (1 à 15, ≤ 160 chacun, distincts casse ignorée, lignes sans caractère visible ignorées), `mesures` facultatives (≤ 8, libellés distincts : `{libelle ≤ 80, unite ≤ 16}`, unité sans libellé refusée), `version` lue → `{version}` : nouvelle version, ou la version lue si rien ne change |

Grille lue : `{corpsEtat, version, adaptee, criteres: [texte], mesures: [{libelle, unite}], adapteeLe, auteur}` (adaptation : date et nom affiché de l'auteur de la version en vigueur ; null pour la grille par défaut). La version 1 est la grille par défaut de l'application (`adaptee` false), dont les textes peuvent s'améliorer avec l'application ; chaque adaptation crée la version suivante du site, jamais modifiée ensuite (table `patrimoine.grilles`, ajout seul, auteur et date). Chaque évaluation (S11-02) enregistre le numéro de version et le texte des points et mesures présentés : son historique ne dépend d'aucune version ultérieure. Erreurs : 422 `donnee_invalide` + `champ` (`criteres`, `mesures`, `version`) ; 409 `modifie_entre_temps` (version dépassée) ; 404 corps d'état inconnu ou site hors périmètre ; 403 sans le droit.

Évaluations (US-11, S11-02) : `/organizations/{orgId}/sites/{siteId}/inventory/components/{composantId}/evaluations…`
| Opération | Accès | Contenu et réponses |
| --- | --- | --- |
| POST evaluations | `EvaluerComposant` (technicien, responsable, délégué) | JSON, ou multipart : partie `demande` (JSON) + jusqu'à 3 fichiers `photos` (10 Mo, JPEG/PNG/HEIC, réencodés). `commandeId` (identifiant d'envoi de l'appareil), `grilleVersion` (version lue de la grille du corps d'état), `constats` (un booléen ou null par point de la grille, dans l'ordre : vrai conforme, faux défaut, null non vérifié ; manquants en fin = null), `mesures` (un nombre ou null par mesure de la grille, ±1 000 000, 3 décimales, zéros de fin retirés), `etat` (Bon, Satisfaisant, Degrade, Mauvais, Critique) pour un composant individuel **ou** `repartition` `{bon, satisfaisant, degrade, mauvais, critique}` (somme = quantité) pour un lot, `remarque` (≤ 2000, multiligne) → `{id, note, libelle, proposerDossier}` |
| GET evaluations | `ConsulterSite` | → `[{id, evalueLe, evaluateurCompteId, evaluateur, grilleVersion, etat, repartition, note, libelle, points: [{texte, conforme}], mesures: [{libelle, unite, valeur}], remarque, photos}]`, la plus récente d'abord (composant retiré compris) |
| GET evaluations/{id}/photos/{rang} | `ConsulterSite` | → `image/jpeg` ; 404 si absente |

Règles : note d'un composant individuel = valeur de l'état (DEC-01) ; d'un lot = moyenne pondérée par les quantités, précision complète ; `note` renvoyée arrondie à une décimale (0,05 vers le haut) et `libelle` lu sur cette valeur arrondie. Photo exigée (422 `photos`) pour « Mauvais » ou « Critique », y compris une seule unité d'un lot ; `proposerDossier` vrai dès qu'un « Critique » est constaté : l'écran propose une déclaration interne préremplie, rien n'est créé. Un lot évalué prend la répartition de l'évaluation dans l'inventaire (journal `Evaluation`, avant et après). L'évaluation enregistre la version et le texte des points et mesures présentés ; elle n'est jamais modifiée. `evalueLe` est l'heure du serveur à la réception : l'instant observé sur l'appareil (évaluation hors connexion, SYNCHRONISATION) sera porté par US-14, avec ses bornes contre l'antidatage. Rejeu du même `commandeId` par le même évaluateur sur le même composant avec le même état ou la même répartition : même réponse, sans second enregistrement (reconnu avant le contrôle de la grille). Erreurs (403/404 d'accès avant les erreurs de saisie) : 422 `donnee_invalide` + `champ` (`commandeId`, `grilleVersion`, `etat`, `repartition`, `constats`, `mesures`, `remarque`, `photos`, `corps`) ; 409 `grille_modifiee` (grille adaptée depuis sa lecture : relire puis refaire), 409 `commande_reutilisee`, 409 `composant_retire`, 409 `modifie_entre_temps` (lot modifié pendant l'enregistrement) ; 404 composant absent ou hors périmètre ; 403 sans le droit.

État du site (US-11, S11-03) : `GET /organizations/{orgId}/sites/{siteId}/inventory/score` — `ConsulterSite`. Recalculé à chaque lecture depuis les évaluations datées (aucun instantané stocké) → `{note, libelle, couverture: {evalues, actifs}, partAncienne, critiques: [{id, nom, zoneId}], zones: [{zoneId, nom, batimentId, batiment, niveau, partiesCommunes, note, libelle, couverture, anciennes, aEvaluer, critiques, plusAncienne, historique}], historique: [{mois: "AAAA-MM", note, libelle}]}`.

Règles (DEC-01, décisions du 29/10) : note d'une zone = moyenne des notes de la dernière évaluation de chacun de ses composants actifs évalués (un lot compte pour un, avec sa note pondérée) ; note du site = moyenne des zones évaluées, Parties communes comprises ; un composant non évalué réduit la couverture sans modifier la note, une zone sans composant évalué n'a pas de note et ne pèse pas sur le site ; composant pris dans sa zone actuelle, retiré exclu à partir de son retrait. Évaluation ancienne : plus de 6 mois, toujours comptée ; `partAncienne` (0 à 1) = poids dans la note du site des composants dont la dernière évaluation est ancienne. `critiques` : composants actifs dont la dernière évaluation constate « Critique » (au moins une unité d'un lot), nommés pour le site, comptés pour chaque zone. `aEvaluer` : composants actifs non évalués ou à évaluation ancienne ; `plusAncienne` : date de la plus ancienne dernière évaluation de la zone. Notes à une décimale (0,05 vers le haut), libellé sur la valeur arrondie, null sans évaluation. Zones : la moins bien notée d'abord, non notées ensuite. Historique (site, et chaque zone, DEC-01) : 12 points mensuels, le plus ancien d'abord, note à la fin de chaque mois (heure de Paris), le mois en cours arrêté à l'instant de la lecture ; null tant qu'aucun composant n'est évalué. Calcul en fractions exactes : une moyenne de moyennes ne perd jamais un arrondi (7,25 → 7,3 ; 3,95 → 4,0 « Degrade »).

Établissement et classement ERP (US-12, S12-01) : `/organizations/{orgId}/sites/{siteId}/inventory/…`
| Opération | Accès | Contenu et réponses |
| --- | --- | --- |
| GET establishment | `ConsulterSite` (T, R/D, P/C) | → `{salariesPresents (null : non déclaré), version (0 : jamais déclaré), batiments: [{id, nom, classement, version}]}` ; `classement` null tant qu'il n'est pas déclaré, sinon `{erp, type, typesSecondaires, categorie, effectif, locauxSommeil, monumentHistorique, permisAvant1997, derniereVisiteCommission}` |
| PUT establishment | `PlanifierPreventif` (R/D) | `salariesPresents` (obligatoire), `version` lue → 204 ; 409 `modifie_entre_temps` si la version est dépassée (première déclaration : `version` = 0) |
| PUT buildings/{id}/classification | `PlanifierPreventif` (R/D) | `erp` (obligatoire), `monumentHistorique` (obligatoire, classé ou inscrit), `permisAvant1997` (Oui, Non, Inconnu), `version` du bâtiment ; ERP : `categorie` (1 à 5, déclarée, jamais calculée), `type` (J, L, M, N, O, P, R, S, T, U, V, W, X, Y ; V par défaut), `typesSecondaires` (5 au plus, distincts du principal), `effectif` facultatif (0 à 100 000), `locauxSommeil`, `derniereVisiteCommission` (date passée, facultative) ; hors ERP, ces champs sont refusés (422 `erp`) → 204 ; sans changement, rien n'est écrit |

Chaque changement est tracé dans `patrimoine.journal_inventaire` (cible `Batiment` ou `Site`, nature `Modification`, champs changés seulement, avant et après, RG-31). Erreurs : 422 `donnee_invalide` + `champ` ; 409 `modifie_entre_temps` ; 404 bâtiment absent ou hors périmètre ; 403 sans le droit. L'application n'affiche jamais « conforme » : le classement ajuste seulement les plans proposés.

Plans proposés (US-12, S12-01) : `GET /organizations/{orgId}/sites/{siteId}/preventive/proposals` — `ConsulterSite`. Calculés à la lecture depuis le catalogue (REGLES « Préventif — règles d'implémentation »), le classement des bâtiments, les salariés présents et les composants actifs soumis à vérification → `[{cle, modele, libelle, nature (InspectionInterne, VerificationExterieure, Entretien), base (Reglementaire, BonnePratique), reference (toujours suivie de « à confirmer »), aConfirmer (vrai), intervenant (TechnicienSite, TechnicienCompetent, OrganismeAgree, Entreprise, CommissionSecurite), periode: {valeur, unite (Semaines, Mois, Ans)}, mode (Glissant, Fixe), echeance (suggérée), cible: {type (Batiment, Composant), batimentId, zoneId, composantId, corpsEtat, libelle}, statut (Proposee, Ecartee), ecart: {motif, commentaire, le, auteurCompteId, auteur} (écartée seulement)}]`, bâtiments d'abord. `cle` = `modele:cible:identifiant`, stable : elle sert à confirmer ou écarter la proposition (S12-02). Une proposition confirmée n'apparaît plus (le plan existe) ; écartée, elle reste listée avec son motif. Rien n'est créé par la lecture.

Plans préventifs (US-12, S12-02) : `/organizations/{orgId}/sites/{siteId}/preventive/…`

| PUT plans/{id} | `PlanifierPreventif` | mêmes champs que la création sauf `commandeId`, `cible` et `nature`, + `version` lue → 204 ; seules les échéances non matérialisées sont recalculées |

## Principes de contrat proposés
Identifiants stables, horodatages avec fuseau, montants avec devise et précision définie, unités explicites.
Commande sensible : clé d’idempotence et version attendue. Même clé/même contenu → même résultat ; même clé/contenu différent → erreur.
Erreurs structurées : code stable, message utilisateur, champs invalides, identifiant de corrélation sans donnée sensible.
Codes indicatifs : 401 session absente, 403 droit insuffisant, 404 objet non visible, 409 conflit, 422 validation, 429 limite. Définir une politique cohérente empêchant l’énumération interclient.
Les événements internes proposés portent identifiant, organisation, type, instant, référence et version ; éviter d’y copier photos/contacts.

## Intégrations
IA : entrée minimisée, sortie structurée avec hypothèses, éléments manquants et sources ; validation serveur avant utilisation.
Produits : source, date, référence, variante, devise, prix, disponibilité et frais connus/inconnus.
Email : destinataires confirmés, PDF validé/versionné, état en file/envoyé/échec ; « accepté par fournisseur » ne signifie pas lu.
Push : indication minimale, lien privé soumis aux droits ; centre de notifications source de vérité.
Fichiers : envoi reprenable, empreinte, métadonnées privées ; contrôle avant rattachement.
